详细报告：① `reports/grpo-v1.md` ② `reports/m6_tax_on.md` ③ `reports/m6_awq.md`

## 2. 结论一：vLLM 部署零精度损耗（② vs ①）

- 总体 F1 +0.15pt（0.8755 vs 0.8740），在 650 条评测的 ±2pt 噪声带内，属采样随机性而非系统差异。
- bf16 引擎（FLASH_ATTN + paged attention + chunked prefill）不引入精度损失；183 s vs ~4.5 min，服务化还带来 ~2.4x 批量吞吐。
- **判定：guardlm-final 以 bf16 vLLM 形态作为生产部署方案，M4 训练成果完整无损地落到服务侧。**

## 3. 结论二：AWQ 4bit 掉点显著，量化通道降级为备选（③ vs ②）

### 3.1 掉点全景

- 总体 F1 **-4.81pt**（0.8755 → 0.8274），远超噪声带；伤害集中在 **Recall -7.65pt**（0.7863 → 0.7098）。
- 混淆矩阵对照：FN 109 → 148（+39 条漏放），FP 5 → 3。模式清晰：**量化把边界样本的 logits 压平，风险判定整体向 none 收缩——漏放增多换误伤减少**。对内容安全场景，漏放（漏检风险内容流出）比误伤代价高得多，此交换不可接受。
- 分档：T1 -3.11pt / T2 -4.53pt / T3 -6.78pt，越难的档掉得越多。

### 3.2 T2 扰动归因（对抗样本受 4bit 权重噪声影响排序）

| 扰动类型 | bf16 对抗 Recall | AWQ 对抗 Recall | 掉点 |
|---|---|---|---|
| homophone（谐音） | 90.9% | 72.7% | **-18.2pt** |
| sp_attack（提示注入/话术攻击） | 73.3% | 64.2% | -9.1pt |
| emoji | 96.0% | 92.0% | -4.0pt |
| pinyin | 76.9% | 73.1% | -3.8pt |
| split（拆字） | 90.0% | 80.0% | -10.0pt |
| fan（繁体） | 93.6% | 93.6% | 0 |

谐音/拆字类对抗依赖对细微字符模式的判别，恰是 4bit 权重噪声最先破坏的能力；语义层对抗（繁体、emoji）几乎无损。**1.7B 小模型权重冗余不足，AWQ 的 1% 显著权重保护策略不足以覆盖本任务的判别敏感区。**

### 3.3 AWQ 收益面

- 体积 3.3 GiB → 1.3 GiB（-61%），推理 183 s → 69 s（吞吐 +165%，marlin 内核批量解码优势）。
- FPR 反而更低（2.14%），none 类召回 97.9% 为三形态最高。

### 3.4 判定

- **生产线维持 bf16 vLLM（guardlm-final），AWQ 不上线**——与 M5 CPT 消融同一决策框架：实验目的（量化掉点边界）已达成，产线不切换。
- guardlm-awq 保留为**低显存/高吞吐场景备选**（如 ≤8 GiB 显卡部署、离线批量初筛），并在 README 中注明精度代价。
- 若后续需要体积压缩，优先级排序：GPTQ-Int8 / INT8 权重量化（掉点预期更小）> AWQ 4bit；或对 AWQ 做量化感知微调（QAT）后再评估。

## 4. 服务化架构要点（M6-2/3/4 交付物）

- **约束解码常开**：`response_format=json_schema`（XGrammar 后端），格式错误率 0.2% → 0.00%；reasoning tax 实测 F1 -0.17pt（噪声内），确认零性能税（压测 structured ON/OFF 吞吐一致）。
- **fail-closed 纪律**：推理后端不可达返回显式 502，解析失败返回 502 + raw 前缀，绝不输出臆造判定；四层解析容错（严格 JSON → 宽松提取 → 兜底）仅在前端，约束解码失败时后端已保证 schema 合法。
- **容量基线**（干净窗口稳态，conc=16）：62.3 req/s / 1527 tok/s / P99 E2E 266 ms / TTFT P99 74 ms；详见 `reports/bench.md`。
- **演示服务**：FastAPI + 静态页（:7860），三示例冒烟通过（常规/黑话/边界各一），后端断连 502 验证通过。
